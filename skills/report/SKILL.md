# Недельный отчёт

Цель — сразу создать черновик письма «Смирнов Д. А. Недельный отчет» в Outlook. **Никогда не отправляй письмо сам** (`outlook send` не используй): только черновик, отправляет пользователь.

Рабочая папка: `W=$(mktemp -d -t weekly-report.XXXX)`, все файлы ниже — в ней.

Jira и Exchange доступны напрямую через VPN (прокси для `.yadro.com` уже отключён через NO_PROXY). Если `jira` или `outlook` пишет «нет связи», попроси включить VPN (`work-vpn`), ничего не обходи сам.

## 1. Активность из Jira

- Если в аргументах передан файл — читай его (это вывод `jira report`).
- Иначе: `jira report > $W/jira.md` (последние 7 дней). Аргументы `--last-week`, `--week`, `--days N` / `-n N` передай как есть.

## 2. Прошлый отчёт из Outlook

```bash
outlook show -f sentitems -s "Недельный отчет" --json > $W/prev.json   # самый свежий мой
jq -r '.sent, (.to | join(", "))' $W/prev.json                     # дата и получатели
jq -r .body $W/prev.json                                           # текст прошлого отчёта
```

Если прошлое письмо старше ~10 дней, предупреди: возможно, найдено не то письмо.

## 3. Составь новый отчёт

Формат как у всей команды (Уткин, Симаков, Беспалов): два раздела верхнего уровня — **Проекты** (плановая работа: эпики, автоматизация, новая функциональность) и **Саппорт** (инциденты, разбор проблем, помощь коллегам, доступы, чистка бэклога). Внутри — подраздел по системе или направлению, в нём пункты.

Пиши `$W/report.txt` — дерево на отступах (4 пробела на уровень), без маркеров и без подписи:

```
Проекты
    Пайплайн пересборки stability
        Восстановлено логгирование на stability: исправлены group_vars, ...
    Конфигурация OpenStack
        Логика prepare вынесена в отдельную роль openstack_prepare (на ревью)
Саппорт
    OpenStack stability
        Найден источник квоты -1 на сетевые ресурсы: квоты сбрасывает qa_user с ВМ из prod_nn ...
    OpenStack
        Найдена причина ошибки terraform с неопознанным пользователем: ...
            По итогам начата работа над исправлением LDAP входа для пользователей КНС (в работе)
        Креды openstack и libvirt сохраняются в Vault для QA тестов
```

Правила:
- **Разделы — только «Проекты» и «Саппорт».** Отдельного раздела «Исследования» нет: разбор проблем и поиск причин — это Саппорт. Подразделы бери из прошлого отчёта, если подходят, иначе называй по системе (OpenStack stability, OpenStack, Terraform…). Пустые разделы не оставляй.
- **Не повторяй прошлый отчёт.** Если что-то уже было упомянуто (даже другими словами), не пиши это снова. Исключение — заметно новый результат по той же теме.
- **Суть, а не история тикета.** Переходы статусов, оценки и смена эпиков — это шум. Главный источник — финальный комментарий при закрытии, его и перефразируй в одну строку в прошедшем времени («Исправлено…», «Добавлен…», «Проведён…»).
- Незакрытое помечай в конце пункта: `(в работе)` для In Progress/Pending, `(на ревью)` для In Review.
- **Пропускай:** тестовые тикеты (summary `test`, `test2`, комментарий «тестовый тикет / не считать в отчет»), эпики без собственного результата, тикеты без содержательных изменений (только «описание изменено», переоткрыт без результата).
- Пачку однотипных инцидентов с одной причиной схлопни в один пункт или опусти, если причина уже была в прошлом отчёте.
- Массовое закрытие старых задач одним махом — это «Проведена чистка бэклога: закрыты неактуальные задачи по …» (в Саппорте).
- Стиль — коротко, по-русски, технические имена как есть (stability, openstack_prepare, keystone).

Не спрашивай подтверждения: сразу переходи к шагу 4.

## 4. Черновик в Outlook — сразу

```bash
python3 ~/.claude/skills/report/scripts/render.py $W/report.txt > $W/report.html
outlook draft \
  -s "Смирнов Д. А. Недельный отчет" \
  -t a.solovev@yadro.com -t RE_infra@yadro.com \
  --body $W/report.html > $W/draft.id
```

- Получатели — как в прошлом письме (`prev.json`). Если они отличаются от указанных выше, используй те, что в `prev.json`, и скажи об этом.
- Подпись (логотип YADRO, должность, телефон, адрес) render.py добавляет сам из `~/.claude/skills/report/signature.html`. Если должность или телефон устарели: `outlook resolve` → поправить signature.html в `/etc/nixos/skills/report/`.

Потом покажи пользователю:
1. Одну строку: черновик создан в «Черновиках» Outlook.
2. Текст отчёта в блоке кода.
3. Коротко «Что не включил»: ключи тикетов и причина.
4. «Что стоит проверить», только если есть реальные сомнения: спорный раздел, пограничная дата.

## 5. Правки

Если пользователь просит что-то поменять: поправь `$W/report.txt`, удали старый черновик (`outlook delete "$(cat $W/draft.id)"`) и создай новый той же командой из шага 4. Дубликаты в «Черновиках» не оставляй.

## Справка по `outlook`

`outlook search|show|draft|send|delete|resolve --help`. Логин и пароль берутся из окружения (`WORK_USER`, `/run/agenix/workpass`), прокси не используется, нужен VPN.
